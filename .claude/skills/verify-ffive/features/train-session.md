# Train a planned session

The Workout tab shows the block's next session inline. The lifter sees per-set targets (or "Calibrate" in week 1), logs weight and reps, and ticks each set's log checkbox. They rate pump, workload, and joint pain once a muscle's last card has no pending set, and answer how a muscle recovered since it was last trained when they first tap a log checkbox for it. Once no set is pending (each is logged or skipped), `Finish Workout` appears pinned above the tab bar. It marks the grid cell done, and the tab moves on to the next day.

## Sub-features

- `session-open` shows the next open session of the block, headed `WEEK n DAY m` (`DELOAD DAY m` in the deload, the weekday in place of `DAY m` on a labeled day) with the subtitle `<day> · <block> · <n> RIR` (`· Deload` in the deload). A day picked from the schedule grid shows instead.
- `session-targets` prefills each set with its target from last week's logs. Focusing a set's weight or reps field shows `We recommend <low>–<high> <unit>` or `We recommend <r> reps or <n> RIR` under the row (`#set.recommendation.N`). While a set has no target weight (week 1), the callout under the exercise name reads `Calibrate · <range> reps at <n> RIR`.
- `session-log` edits `Set n weight` and `Set n reps` and ticks `Log set n`, which carries the Selected trait while logged.
- `session-feedback` shows the "How did <muscle> feel today?" card (`#feedback.open.<muscle>`) under the muscle's last card once that card has no pending set (logged or skipped) and the muscle logged at least one set this session. A muscle whose sets were all skipped gets no card and no sheet (`journeys/skipped-muscle-feedback.steps`). The card opens a sheet with Pump, Workload, and Joint pain chips; the sheet also opens on its own when that last set is logged. `#feedback.save` is disabled until all three are answered and writes them; `#feedback.cancel` drops the draft. Tapping a selected chip clears it. While a finished muscle has no saved feedback, logging a set on another muscle shows `#feedback.required` ("Rate <muscle> first") and opens that muscle's sheet instead. Journey: `journeys/train-session-seeded.steps`.
- `feedback-help` puts a `?` button beside each Pump, Workload, Joint pain and Soreness question (`#chip.help.<question slug>`, as in `#chip.help.joint-pain` and `#chip.help.soreness-after-that-session`). It toggles a list of every answer with its one-line meaning, from each enum's `meaning`. Journey: `journeys/feedback-help.steps`.
- `joint-pain-menu` reports joint pain mid-session from `#exercise.menu.<n>`, then `#menu.joint-pain` and a level by label (`button "A lot"`). It writes the muscle's feedback record for this session, so the end-of-muscle card opens with that chip selected. Block sessions only; quick workouts have no entry. Journey: `journeys/joint-pain.steps`, after `plan-mesocycle.steps` on a fresh store; it checks `store-expect MuscleFeedbackRecord jointPainRaw 3`, relaunches, and asserts `selected #chip.a-lot`.
- `session-soreness` asks "How did your <muscle> recover?" in a sheet when the lifter taps the log checkbox of the muscle's first set, if the block's latest earlier finished session logged that muscle and recorded feedback for it with no soreness yet. `#soreness.save` is disabled until a chip is picked; it records soreness, changes only how many sets the muscle has (every set already there keeps its weight, reps, type and skip), and logs the tapped set. Journey: `journeys/recovery-keeps-sets.steps`, on a fresh store. `#soreness.cancel` leaves the set unlogged. With no feedback given last time, no question shows. While another muscle's feedback is owed, every other exercise card is greyed out and a log tap shows `#feedback.required` centered on that card.
- `session-skip-sets` skips one pending set from `Set n Menu` (`Skip Set`, then `Unskip Set` to undo) or every pending set of a card from `Exercise Menu` (`Skip Remaining Sets`). A skipped row dims its fields and its log checkbox reads `Skipped` as its value. Logging a skipped set replaces the skip. A logged set offers no `Skip Set`.
- `session-finish` finishes the session with `Finish Workout`, marks the cell finished, and shows the next day. The button exists only while every exercise has sets and none of them is still pending (each is logged or skipped). Deleting unlogged sets or removing unlogged exercises also brings it up.
- `session-pinned` keeps the `WEEK n DAY m` header (with `Schedule` and `Workout Menu`) at the top and `Finish Workout` above the tab bar while the cards scroll.
- `session-tools` covers each card's `Technique cue`, `History`, and `Exercise Menu` (Swap Exercise on block days, disabled once a set on the card is logged, Add Set, Skip Remaining Sets, Joint Pain, Add/Edit Note, Delete Note, Remove Exercise), and each row's `Set n Menu` (`Set n Menu, <type>` on a non-regular set; Add Set, Skip/Unskip Set, Set Type, Delete Set). Delete Set and Remove Exercise are driven by `train-session.steps`. Swap Exercise asks "Later Weeks Too" (`#dialog.swap-later-weeks`) or "This Session Only" (`#dialog.swap-session`) after the pick; `swap-exercise.steps` drives both scopes across three weeks. Technique cue and History are not yet driven.

## How to get to it (user POV)

- Workout tab: the block's next open session shows as soon as the tab opens, unless a quick workout is open, which shows first.
- Workout tab, `Schedule` button: in the sheet's grid, tap a current-week `play.circle.fill`, `circle.lefthalf.filled`, or `circle` cell to show that day on the Workout tab.
- Mesos tab, the block's row: the detail page has the same grid. A current-week cell switches to the Workout tab on that day.
- Either grid: tap a finished `checkmark.circle.fill` cell to review it read-only (WorkoutDetail).

## Driving it with ffive-verify

Preconditions:

- On-disk: plan-mesocycle.steps ran on this store, so "Verify Block" shows Week 1 · Day 1. Journey: `journeys/train-session.steps`.
- Demo: `launch -seedDemo` (Week 2 · Day 1 in progress, quads logged). Journey: `journeys/train-session-seeded.steps`.

- **Open (on disk).** Relaunch onto the Workout tab. Steps: `launch`, `wait text "WEEK 1 DAY 1" timeout=20`, `wait text "Bench Press"`, `wait text "~Calibrate"`.
- **Log a set.** Enter 135 × 9 in set 1 and log it. Steps: `replace #set.weight.1 "135"`, `replace #set.reps.1 "9"`, `value #set.weight.1 "135"`, `value #set.reps.1 "9"`, `tap #keyboard.done`, `tap #set.log.1`, `selected #set.log.1`.
- **Finish gate.** After set 1 is logged, `absent #workout.finish`. The journey then stops early the way a lifter would. It taps `#set.menu.2`, then `#menu.delete-set`, for Bench's unlogged sets, and `#exercise.menu.2`, then `#menu.remove-exercise`, for each other exercise. Card ids follow card position, so the second card is `#exercise.menu.2` after every removal. Finish stays absent until the last unlogged set is gone. Deleting Bench's last unlogged set finishes chest, which opens its feedback sheet on its own: `wait #feedback.save`, `tap #feedback.cancel` before the removals.
- **Finish.** Steps: `wait #workout.finish`, `tap #workout.finish`, `wait text "WEEK 1 DAY 2" timeout=10`, `store-expect SetEntry weight 135`, `store-expect SetEntry reps 9`. In the `Schedule` sheet, the W1 D1 cell becomes `checkmark.circle.fill`.
- **Proof (on disk).** The journey's `store-expect` steps check the logged weight and reps. For the full row, run `ffive-verify store "select w.ZWEEK, w.ZDAYINDEX, w.ZENDDATE is not null as finished, s.ZWEIGHT, s.ZREPS, s.ZISDONE from ZWORKOUT w join ZEXERCISE e on e.ZWORKOUT = w.Z_PK join ZSETENTRY s on s.ZEXERCISE = e.Z_PK where w.ZMESOCYCLE is not null and s.ZISDONE = 1"`. It returns `0 | 0 | 1 | 135.0 | 9 | 1`.
- **Skip sets (on disk).** After plan-mesocycle, `journeys/skip-sets.steps` logs set 1, skips set 2 (`#set.menu.2`, `#menu.skip-set`, `value #set.log.2 "Skipped"`, `store-expect SetEntry isSkipped 1`), undoes and redoes the skip, then taps `#exercise.menu.<n>`, `#menu.skip-remaining` for all six cards. Only chest, with its logged set, asks for feedback. `Finish Workout` stays absent until the last card is skipped, and set 2 still reads `Skipped` after a relaunch. For the rows, run `ffive-verify store "select ZISDONE, ZISSKIPPED, count(*) from ZSETENTRY group by 1,2"`.
- **Targets and feedback (demo).** The in-progress session is already on the Workout tab, with quads finished and unrated. See `journeys/train-session-seeded.steps`: tapping Bench's first `#set.log.1` (after `scrollto #set.log.5`) shows `#feedback.required` and opens the quads sheet; answer the three chips, `tap #feedback.save`, and the card shows `image "checkmark.circle.fill"`.
- **Soreness (demo).** After the quads feedback, tap Bench's first `#set.log.1` (after `scrollto #set.log.5`): the chest sheet opens; `tap #chip.healed-just-in-time`, `tap #soreness.save`, then `selected #set.log.1`. See `journeys/train-session-seeded.steps`. The answer re-plans that muscle's sets only when the soreness belongs to this day's session last week (`MesoPlanner.recordSoreness`).

## Gotchas

- An empty set field shows its placeholder: the unit for weight, `<n> RIR` for reps (`reps` in a deload). A zero weight or zero reps reads as empty. Assert typed values with `value #set.weight.<n>`, not by matching the field's text.
- The session is a lazy stack, so cards below the fold are not in the tree. Scroll before asserting on them.
- XCUITest calls a chip under the pinned header hittable, but a tap there lands on the header. `scrollto` brings its target to the middle half of the screen, so tap a chip only after a `scrollto` on it or on a neighbor.
- Feedback chips carry the Selected trait. The header checkmark proves all three questions are answered.
- Feedback and soreness written in a `-seedDemo` run vanish on relaunch. Prove their persistence on the on-disk path. A soreness question needs feedback given for that muscle in the previous session.
- The decimal pad covers the lower part of the list and hides the tab bar. Tap `#keyboard.done` before tapping anything it might cover.
- `Finish Workout` is absent from the tree while any set is pending (neither logged nor skipped), so a `wait` or `tap` on it times out while any set is open.
- Remove Bench's other exercises while one Bench set is still unlogged. A fully logged Bench adds the chest feedback card, which pushes the next card's `Exercise Menu` off screen.
- The tab builds a block day as soon as it shows it, so an open `ZWORKOUT` row is no proof that training started. Until a set is logged, the day's start time resets each time the tab shows it.
- The `Workout Menu` items do not appear in `tree` dumps, but tapping them by id works.
